# 保全排班系統 (PHP+MySQL) 開發規劃紀錄

**日期：** 2026-03-05
**專案目標：** 將 Google Sheets 班表升級為具備自動校驗與交互功能的 Web 系統。

---

## 1. 資料庫架構設計 (Database Schema)

### A. 員工表 (employees)
*   **用途：** 儲存所有保全、行政、清潔人員的基本資訊。
*   **關鍵欄位：**
    *   `id`: 唯一識別碼 (Primary Key)。
    *   `name`: 姓名。
    *   `phone`: 聯絡電話。
    *   `role`: 職務類別 (正職, 機動, 兼職, 組長)。
    *   `status`: 在職狀態 (1: 在職, 0: 離職)。
    *   `max_mandatory_off`: 每月最大必休天數 (預設 3 天)。
    *   `note`: 備註。

### B. 社區案場表 (sites)
*   **用途：** 儲存社區的基本資料。
*   **關鍵欄位：**
    *   `id`: 唯一識別碼。
    *   `site_name`: 案場名稱。
    *   `address`: 地址。

### C. 職位/哨位表 (posts)
*   **用途：** 定義每個案場具體需要的崗位，解決單日班、多哨位、行政人員混雜問題。
*   **關鍵欄位：**
    *   `id`: 唯一識別碼。
    *   `site_id`: 所屬案場。
    *   `post_name`: 崗位名稱 (大門哨, 巡邏哨, 總幹事, 秘書, 清潔員)。
    *   `category`: 分類 (保全, 行政, 環保)。
    *   `shift_pattern`: 班制屬性 (日班固定, 夜班固定, 兩班倒)。

### D. 排班紀錄表 (schedules)
*   **用途：** 核心排班資料。
*   **關鍵欄位：**
    *   `employee_id`: 員工 ID。
    *   `post_id`: 哨位/職位 ID。
    *   `work_date`: 日期。
    *   `shift_type`: 班次 (A/B/必/休)。
    *   `work_type`: 出勤屬性 (正職, 機動/支援)。

### E. 預約休假表 (leave_preferences)
*   **用途：** 員工選擇休假志願，實現「先填休假、後排班」的半自動化。
*   **關鍵欄位：**
    *   `employee_id`: 員工 ID。
    *   `request_date`: 日期。
    *   `type`: '必休' (Mandatory) 或 '想休' (Optional)。
    *   `status`: 審核狀態。

## 2. 核心功能邏輯

### A. 跨案場支援與防撞校驗
*   **邏輯：** 當員工張三在 A 案場已有排班時，若嘗試在 B 案場排入同日班次，系統應執行 SQL 查詢確認當日無重複。
*   **結果：** 若偵測到衝突，前端彈出重複排班警告。

### B. 預約休假與人力預警
*   **流程：** 
    1. 每月 20-30 號開放員工填寫「必休」(限額) 與「想休」。
    2. 管理員排班時，系統自動標示日期顏色 (紅:必休, 黃:想休)。
    3. **人力缺口檢查：** 若某案場單日請假人數過多，系統自動預警防止空班。

### C. 交互式介面設計
*   **摺疊功能：** 案場資料預設摺疊，點擊展開。
*   **彈窗查詢：** 點擊員工姓名，透過 AJAX 調用該員全月班表 Modal，不切換頁面。
